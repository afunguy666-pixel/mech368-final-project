# MECH 368 移动机器人起步工程

[English](README.md) / 中文版

> 本文是 [README.md](README.md) 的中文对照版。代码、注释和程序输出都是英文；两个版本如有出入，以英文版为准。

这是两块 Arduino Nano 33 BLE Sense Rev2 开发板的开发框架：一块装在机器人上，一块装在手持遥控器里。
第一阶段实现了 BLE 指令/状态传输、可移植的数据包校验，并接入了现有的运动许可状态机。
遥控器目前只发送零速心跳包，或者由串口触发的急停（E-stop）。
所有实际的电机输出都还没有实现（处于禁用状态），也没有假定任何驱动器引脚。
这还**不是**一台能工作的机器人，不是经过验证的安全系统，也不是可以提交的项目。

报文的精确格式、时序、初始化 API 的阻塞限制以及尚未完成的硬件测试，见
[BLE 协议与台架检查清单](docs/BLE_PROTOCOL.zh-CN.md)。

| 路径 | 用途 |
| --- | --- |
| `firmware/robot/` | 机器人程序；BLE、本地恢复和电机输出闸门的集成点 |
| `firmware/remote/` | 遥控器程序；姿态估计、BLE 和急停请求的集成点 |
| `libraries/Mech368BLE/` | 可移植的报文编解码、接收器和遥控器端 ACK 跟踪 |
| `libraries/Mech368Safety/` | 可移植的状态机，与主机测试共用 |
| `tests/` | 针对看门狗和急停行为的确定性主机测试 |
| `.github/workflows/ci.yml` | 相互独立的主机测试、固件模拟和开发板编译任务；不会烧录任何开发板 |

## 在本地运行

在 Linux/macOS 上，或在工具已加入 PATH 的 Windows Bash 环境中：

```sh
bash scripts/test-host.sh

# 需要 PATH 中有 Arduino CLI 1.3.1（与 CI 使用的工具链相同）。
arduino-cli core update-index
arduino-cli core install arduino:mbed_nano@4.4.1
arduino-cli lib install ArduinoBLE@1.4.1
bash scripts/compile-firmware.sh
```

主机测试需要 C++11 编译器，必要时用 `CXX` 指定。两个脚本都只编译，不会烧录硬件。
Arduino 的 [Rev2 手册](https://docs.arduino.cc/tutorials/nano-33-ble-sense-rev2/cheat-sheet/)
指明使用 Mbed OS Nano 软件包，编译目标为 `arduino:mbed_nano:nano33ble`。

## 在台架上实现与验证

1. **BLE 与姿态控制。** 用两块实际的开发板验证，确认由哪一端广播。
   测量 BLE 处理延迟，包括同步的初始化调用。把校准后的遥控器横滚角和俯仰角
   映射为线速度和角速度。检查已实现的指令单位、取值范围、报文格式以及
   序列号/会话处理。在刷新看门狗之前，先校验类型、长度、版本、范围和新鲜度；
   缓存的、格式错误的、重复的或过期的报文都不能延长看门狗。
   一旦报告断开就立即处理，并在每个设备上实现要求的断链 LED
   （包括遥控器检测"对端已失去响应"的情况）。
2. **电机禁止与时序。** 状态机在最后一个新的有效运动报文之后 450 ms 超时，
   为调度和输出延迟留出 50 ms。这并不是对硬件时序的保证。
   先把电机从电气上断开，抓取最后一个被接受的报文和确认后的归零/禁用输出，
   证明在观测到的最重轮询负载下，端到端延迟不超过 500 ms。
   测试以下情况：启动时没有报文、报文中断、无效报文、突然断开和重新连接。
   在接上电机电源之前，确认电机驱动器的实际极性、禁用行为和上电默认状态。
   所有驾驶模式必须共用同一个输出闸门。
3. **急停。** 证明有效的遥控器急停优先于运动指令，也优先于同时发生的恢复手势；
   断开连接后仍保持锁存，并忽略之后的驾驶指令。
   在本地 APDS-9960 上产生一个新的手势事件来解除锁存；确认解除后，
   在收到下一条有效指令之前运动仍被禁止。这里的锁存只保存在 RAM 中。
   验证启动/复位后物理输出处于禁用状态；在允许电机复位后运行之前，
   先定义一个明确的重新使能策略。
4. **课程要求的其余硬件。** 验证醒目的低电量指示器及其在你们电池组上的阈值。
   测定车轮方向和编码器标度，验证差速转向，然后对照课程讲义测试
   红外巡线、避障、IMU/里程计位姿跟踪和建图。电机测试开始时让车轮悬空，
   并准备一个独立、安全的断电手段。记录测量数据和观察到的行为，
   不要把"编译通过"当作验收。

## 固件在环（firmware-in-the-loop）模拟器

只需要 Bash 和 C++17 编译器，就能在两块虚拟开发板上运行**未经修改的**
`robot.ino` 和 `remote.ino`。两块板之间用模拟的 BLE 无线链路相连，
机器人板接一辆虚拟小车（电机、编码器、巡线传感器、超声波、IMU、手势、电池、温度），
小车跑在按讲义场地图绘制的虚拟场地上：

```sh
bash scripts/run-fw-sim.sh                   # 运行全部场景
bash scripts/run-fw-sim.sh estop_latch       # 运行单个场景并输出完整日志
bash scripts/run-fw-sim.sh --seeds 20 link_stability   # 用 20 个随机种子反复运行
```

每次运行都会在 `build/fwsim/` 中生成可交互的 HTML 回放以及 CSV 和日志文件。
接线、几何参数和场地都是文本文件，分别在 `sim/vehicles/` 和 `sim/worlds/`；
测试场景是 `sim/fwsim/scenarios/` 中的 C++ 文件。API、模型、模型的局限，
以及对第一阶段链路时序的发现，见 [docs/SIMULATOR.zh-CN.md](docs/SIMULATOR.zh-CN.md)。

| 路径 | 用途 |
| --- | --- |
| `sim/fwsim/hostduino/` | 在电脑上替代 Arduino 核心库、ArduinoBLE、BMI270/BMM150 IMU、APDS-9960、HS300x 的模拟库 |
| `sim/fwsim/` | 虚拟开发板、无线链路、小车/场地模型、回放查看器、测试场景 |
| `sim/examples/line_follower/` | 驱动虚拟小车的示例程序（不是课程固件） |

## 软件在环（SIL）模拟器

不需要 Arduino、BLE 硬件、Python 或网络，就能运行主机测试并生成五个 CSV 轨迹：

```sh
bash scripts/run-sil.sh
```

轨迹输出到 `build/sil/`；把目录作为第一个参数传入可以更改输出位置。
用 `CXX` 选择 C++11 编译器。请在 Bash 中运行（例如 Windows 上的 Git Bash 或 WSL，
且编译器在 PATH 中）。CI 的主机测试任务也会运行这条命令；原有的固件编译任务保持独立。

如果装了 Python 和 matplotlib，还可以从 CSV 目录生成 `tracking.png` 和 `watchdog.png`（可选）：

```sh
python sim/plot.py build/sil
```

模拟器以 **10 ms 为步长推进虚拟时钟**，不会真的等待。
一个脚本化的遥控器每 50 ms 生成一条指令，把正确编码的报文放进进程内队列，
队列有固定 20 ms 的投递延迟和按脚本设定的丢包时段。
真实的可移植 `Receiver` 及其 `MotionSafety` 实例先对指令值进行闸门控制，
运动学模型再使用这些值。脚本化遥控器会立即读取挑战码/状态；
这个模拟器不模拟实际的 BLE 协议栈、时序、链路预算，也不运行遥控器固件。

| CSV | 测试检查的内容 |
| --- | --- |
| `straight.csv` | 理想直线运动：第一条指令被接受后 2 s 内走 0.50 m；两个估计器的结果在编码器分辨率范围内一致。 |
| `turn90.csv` | 先直行 1 秒（0.25 m），再以 1.571 rad/s 原地旋转 1 秒：转过接近 90°，且没有额外平移。 |
| `sensor_error.csv` | 直行/原地转/直行，固定随机种子 368，左右轮相反的 2% 标度偏差，有界的编码器/陀螺仪噪声，以及固定的陀螺仪零偏。测试检查可重复性和误差为有限非零值，而不是假定融合一定更好。 |
| `watchdog.csv` | 在虚拟连接仍保持的情况下，指令在 970 ms 归零（最后接受于 520 ms + 450 ms）。1070 ms 的新报文恢复控制。1300 ms 主动断开后指令立即归零；1450 ms 重连后仍保持禁止，直到 1470 ms 收到新报文。 |
| `estop.csv` | 320 ms 的急停把两轮指令都置零，并在断开/重连后保持。900 ms 的一个合成**本地**手势解除锁存，但指令仍为零，直到 920 ms 收到新报文。 |

每一行记录接收器状态、经过闸门的底盘指令（mm/s 和 mrad/s）、车轮指令（rad/s），
以及三组 XY/偏航角位姿（m 和 rad）。位姿取的是该时间戳上、把指令应用到下一个
10 ms 区间之前的值；偏航角不做 ±π 折返。事件标签标记报文投递/丢弃、看门狗超时、
断开、重连、急停和本地恢复。

虚拟几何参数为轮距 0.10 m、车轮半径 0.020 m，每转 1024 个编码器计数。
这些参数和噪声/零偏参数都集中在 `sil::Config`（`sim/Simulation.h`）中，
可以传给 `sil::run`。默认的 CSV 使用代码内的默认值。编码器增量取自相邻两次
四舍五入后的累计计数，以免小增量被反复舍掉。真值是理想的差速运动，
没有打滑、惯性或制动动态。两个估计器使用相同的车轮增量计算距离；
纯编码器的偏航角来自左右轮增量之差，而融合后的偏航角增量是固定的
10% 编码器 / 90% 陀螺仪加权。这些权重和零偏只是示意，并未标定。
这里误差更小，并不代表在真实机器人上的表现，也不保证这种加权在其他条件下有帮助。

SIL 验证的是给定脚本下的闸门逻辑和模型，而不是硬件的停车行为。
在接上电机电源做带载测试之前，仍需在台架上验证实际的 BLE 交互、循环和驱动器延迟、
急停/重新使能的 I/O、编码器标度、陀螺仪校准以及机械行为。
